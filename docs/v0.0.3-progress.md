# Cdatra v0.0.3 — notas de progresso

## Objetivo

A v0.0.2 deixou a base pronta: SQL parametrizado, dialetos, H2 e Cloudflare D1, e `CdatraException` como erro único.
Na v0.0.3, o Cdatra deve ficar **completo o bastante para montar a camada de banco dos meus sistemas**,
pessoais e do trabalho, sem precisar escrever SQL à mão nos casos comuns.

O que falta não é arquitetura, é cobertura: tipos, consultas, operações de escrita, transações e restrições de schema.

**Roteiro:** v0.0.3 = ORM completa para entidades isoladas. v0.0.4 = relações (`@ManyToOne`, joins) e migrações.

**Linha de base herdada da v0.0.2: 582 testes no Java e 37 no Worker.**

## Prioridades

A ordem importa: cada fase usa o que a anterior deixou pronto.

### Fase 0 — Ajustes que quebram a API

Feitos primeiro porque quebram a API, e ainda não há sistemas usando a lib.

- Corrigir a grafia de `tableNaame` (`@Entity`) e `columName` (`@Column`).
- Nome opcional: sem nome na anotação, usar o nome da classe ou do campo.
- A decidir: o nome novo dos atributos (`name`, como no JPA, ou `tableName`/`columnName`) e a conversão automática
  (`createdAt` → `created_at` ou o nome exato do campo).

### Fase 1 — Tipos novos

Sem eles, quase nenhuma entidade real cabe no Cdatra.

- Datas: `LocalDate`, `LocalDateTime`, `Instant`.
- `BigDecimal` (valores em dinheiro, sem erro de arredondamento do `double`).
- `enum` (a decidir: gravar o nome ou a posição; o nome é o padrão mais seguro).
- `UUID`.
- Cada tipo passa por `TypeMapper` → `SqlType` → `SqlDialect.typeName` na ida e pelo `ValueConverter` na volta.
  No D1, a ida também passa pelo `D1DatabaseAdapter` (o JSON não tem data nem decimal).

### Fase 2 — Consulta fluente

É o ganho de expressividade principal da versão. Os `QueryCondition` e `QueryFilter` atuais viram a base por baixo.

```java
List<User> users = repository.query()
        .where("name", Operator.LIKE, "Car%")
        .and("age", Operator.GREATER_THAN, 18)
        .orderBy("name")
        .limit(10)
        .list();
```

- `ORDER BY` (crescente e decrescente), `LIMIT`/`OFFSET` (paginação).
- `count`, `exists`, `first` (um resultado ou `null`).
- Operadores novos: `IN`, `BETWEEN`, `IS NULL`/`IS NOT NULL` explícitos.
- Os métodos `findBy`, `findByConditions` e `findByFilters` continuam funcionando.

### Fase 3 — Operações de escrita

Completa o CRUD.

- `deleteById`, `saveAll` (vários registros de uma vez).
- `update` e `delete` com condição (usando o mesmo `where` da fase 2).
- Devolver o número de linhas afetadas (no D1, pelo `meta.changes`, que ficou pendente da v0.0.2).

### Fase 4 — Transações e batch

Garante que um conjunto de operações acontece inteiro ou não acontece.

- JDBC: `commit` e `rollback` na `Connection`.
- D1: rota `POST /v1/batch` no Worker (o D1 não tem `BEGIN`/`COMMIT`; o `batch` é atômico).
- A decidir: o formato da API pública que sirva aos dois bancos (por exemplo, `repository.transaction(...)`
  recebendo as operações), já que o D1 não deixa abrir uma transação e decidir no meio do caminho.

### Fase 5 — Schema e erros

Dá robustez ao uso real.

- `@Column` com `nullable`, `unique` e `length`.
- `createTableIfNotExists` e `dropTable`.
- Subclasses de `CdatraException` (por exemplo, `ConstraintException`), sem quebrar quem faz `catch (CdatraException e)`.
  No Worker, `CONSTRAINT` vira HTTP 409, com o índice do comando que falhou.

### Fica para depois (v0.0.4 ou mais)

- Relações (`@ManyToOne`, `@OneToMany`) e joins.
- Migrações de schema.
- Descobrir o dialeto por `connection.getMetaData().getDatabaseProductName()`.
- No Worker: `GET /v1/health`, BLOB em base64 e as métricas `rows_read`/`rows_written`/`duration`.

## Decisões

- **Atributo `name`** em `@Entity` e `@Column` (`@Entity(name = "users")`, `@Column(name = "id")`), como no JPA:
  a própria anotação já diz se é tabela ou coluna.
- **Nome padrão em snake_case:** sem `name`, o campo `createdAt` vira a coluna `created_at`, e a classe `UserAccount` vira a tabela `user_account`.
  É a convenção do SQL (Rails, Django, Spring Boot). Sem a conversão, o H2 guardaria `createdAt` como `CREATEDAT`, sem a separação das palavras.
  Sem plural automático (`User` → `user`, não `users`), como no JPA.
- A regra do nome padrão fica num lugar só. Hoje `Analysis`, `ValueAnalysis` e `ObjectMapper` leem o nome direto da anotação.
